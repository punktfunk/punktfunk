## Guided install (preview)

On Linux, one command does what the pages above walk you through — detects your distro, adds the
repo, installs the host, notices a Sunshine/Apollo/Vibeshine already on the box and moves one port
so both can run, joins the `input` group, opens the firewall if you run one, starts the host and the
console, and tells you how to pair:

Prefer to read what runs first:

<Installer inspect />

That URL serves a short shell stub. It checks you are on a Linux architecture it has a build for,
downloads the `punktfunk-setup` installer, verifies its sha256 and runs it — nothing else. The
stub has no options of its own: everything you pass, and every `PUNKTFUNK_INSTALL_*` variable in
your environment, is handed to the installer untouched.

With a terminal you get a single screen showing every choice already resolved: press Enter to
install, or move to a row and edit it. The install itself reports one progress line rather than a
running log; `-v` echoes every command instead. Without a terminal — piped, in CI, or with
`--yes` — it prints the same choices as plain lines and takes the defaults.

The defaults follow the box. Bazzite and Nobara linger; a seatless SSH session lingers; an active
Sunshine/Apollo host opts into Moonlight compat; the clipboard is shared. The full controller
(joining the `punktfunk` group, which grants usbip attach) is **on by default on every box** —
`--no-punktfunk-group` or `PUNKTFUNK_INSTALL_PUNKTFUNK_GROUP=0` opts out.

`--host` and `--client` choose what to install; `--client` alone installs just the client, from
your distro's repo where it carries one and as a user-scope flatpak where it does not — so a
distro with no punktfunk repo can still run the client. After the password step it asks where the
web console should be reachable — your local network (the default), this machine only, or one
address such as a VPN interface; `--web-bind=localhost|lan|ADDR` answers it without the question and writes
[`PUNKTFUNK_UI_BIND`](/docs/configuration) to `host.env`. `--channel stable|canary`, `--mgmt-port`,
`--no-start`, `--dry-run` and `--uninstall` work as before, and each has an environment twin
(`PUNKTFUNK_INSTALL_YES`, `PUNKTFUNK_INSTALL_CHANNEL`, `PUNKTFUNK_INSTALL_GAMESTREAM`,
`PUNKTFUNK_INSTALL_CLIPBOARD`, `PUNKTFUNK_INSTALL_PUNKTFUNK_GROUP`, `PUNKTFUNK_INSTALL_LINGER`,
`PUNKTFUNK_INSTALL_CONSOLE_CERT`, `PUNKTFUNK_INSTALL_OMARCHY_SETUP`,
`PUNKTFUNK_INSTALL_OMARCHY_TOASTS`, `PUNKTFUNK_INSTALL_OMARCHY_IDLE`,
`PUNKTFUNK_INSTALL_OMARCHY_THEME`, `PUNKTFUNK_INSTALL_MGMT_PORT`,
`PUNKTFUNK_INSTALL_WEB_BIND`, `PUNKTFUNK_INSTALL_DRY_RUN`).
`--help` lists them all. `--demo <preset>` walks the whole flow against a canned machine and
changes nothing, which is the honest way to see what it would do before letting it near a box.

It covers Ubuntu/Debian, Fedora, Arch-family, Bazzite/Fedora Atomic and SteamOS; NixOS and Windows
it points at their pages. On SteamOS there is no package to install — it clones the source and runs
the on-device build, which takes about 25 minutes on a first run and does the groups, linger and
service start itself, so the installer hands over and stops there. **Preview:** the per-system
pages above remain the documented path, and
the installer runs exactly the install commands they show — it generates them from the same source
this site quotes, so the two cannot drift. Re-running is safe.

`--channel` also **switches** a host that is already installed — see
[Release Channels](/docs/channels#switch-an-installed-box-between-channels). Without the flag the
script follows whichever channel the box is already on, so re-running it to fix a group or a
firewall rule never moves you off canary.

## Good to know

- **Read [Security & Safe Use](/docs/security) once.** A streaming host is remote control of the
  machine: keep it on your LAN or a VPN, and keep pairing on (the default).
- **Already running Sunshine, Apollo or Vibeshine?** They can coexist, with one port moved — see
  [Switching from Sunshine](/docs/switching-from-sunshine) before you install.
- **What gets installed.** `punktfunk-host` is the host; `punktfunk-web` is the browser console
  (pairing, status, library); `punktfunk-scripting` is the plugin runner that brings your game
  launchers into the [library](/docs/game-library) (started for you everywhere except Arch and
  source builds — `systemctl --user enable --now punktfunk-scripting` there). Every install line
  on these pages names all three. The host package only *recommends* the console, and a package
  manager set to skip weak deps (`install_weak_deps=False`, `APT::Install-Recommends "0"`) would
  otherwise leave you with a host and no way to pair with it. The Bazzite image contains all
  three already.
- **Stable by default.** Every guide points at the **stable** channel, which moves on `vX.Y.Z`
  releases. The latest `main` build is the **canary** channel — [Release Channels](/docs/channels).
- **Updating and removing** are one page each: [Updating the Host](/docs/updating) (the console
  tells you when a newer build is out) and [Uninstall](/docs/uninstall).
- **No package for your platform?** [Build from source](/docs/build-from-source).
