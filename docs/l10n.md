# Localization

Every word a person reads in Punktfunk is written once, in `l10n/messages`, and each platform's
build compiles it into its own form: Rust functions, Android resources, an Apple String Catalog,
Paraglide for TypeScript. Nothing generated is committed. This page is what a contributor needs;
[`l10n/README.md`](../l10n/README.md) has the mechanics and [`l10n/SPEC.md`](../l10n/SPEC.md) the
format. How to word a message: [`docs/writing.md`](writing.md) §4b and §4d.

## Where messages live

`l10n/messages/<part>/<lang>.json` is one flat JSON object per language; `en` is the source.
`notes.json` beside it gives each key one line for the translator: where it shows, and what
each placeholder holds. Every message with a placeholder has a note.

A message goes in the **widest part where it is true word for word and stands for the same
thing**. A platform part never redefines a shared key.

| Part | Holds | Read by |
|---|---|---|
| `common` | Text with no context: a button's verb (Cancel, Retry), a unit, a product term | everything |
| `client` | What every client says: player settings, pairing, hosts, connecting, the library, the stream overlay, quick actions, client errors | the kit, Apple, Android, GTK, WinUI, the browser, Decky |
| `console` | The controller interface the kit alone draws, and the own text of the TV and console clients | the kit and what embeds it |
| `desktop` | The GTK and WinUI shells: window chrome, menus, keyboard-only text | GTK, WinUI |
| `apple`, `android` | Text only that platform has: widgets, intents, the notification, permission dialogs | that platform |
| `browser`, `decky` | The browser client's shell, the Decky plugin | that client |
| `host` | What the host sends as an id: reject reasons, API errors, diagnostics | every app that shows it |
| `tools` | Setup, the Windows wizard, the tray, the updater | those binaries |
| `web` | The web console | the web console |

## Keys

- `<area>_<thing>[_<role>]`, lowercase `snake_case`, two words at least. The bare key is the
  label; roles are `_hint`, `_title`, `_body`, `_confirm`, `_failed`, `_a11y`.
- **Unique across every part**, `web` included. Search all of them before you name one.
- A player setting is `player_<catalogue key>`, its hint `player_<key>_hint`, an option
  `player_<key>_<option>`. `clients/shared/settings-catalog.json` lists the keys and the option
  ids and carries no words; every client's test checks its screen against it (`docs/settings.md`).
- A key in a platform part starts with the part's name: `console_`, `desktop_`, `apple_`,
  `android_`, `browser_`, `decky_`. In `tools`: `setup_`, `wizard_`, `tray_`, `updater_`.

## Add a message

1. Search every part for the text and its meaning. Reuse a message only where it stands for the
   same thing (§4d "Share a message, never a word").
2. Add the key to `l10n/messages/<part>/en.json`, a note to `notes.json` if it has a placeholder.
3. Run `cargo run -p pf-l10n -- check`.
4. Call it ([`l10n/README.md`](../l10n/README.md) "Add a message"):

| Where | Call |
|---|---|
| Rust | `pf_l10n::client::player_stats_scale_pct()`, with the part's feature on `pf-l10n` |
| Kotlin | `stringResource(R.string.key)`, `pluralStringResource(R.plurals.key, n, n)` |
| Swift | `L10n.playerStatsScalePct`, `L10n.prefsAdvancedChanged(n)` |
| TypeScript | `m.key()` |

Arguments follow the order the English shows them. Do not reword or rename a message that
exists: one edit changes every platform, and the maintainer approves wording.

**Text is never identity.** Do not compare, parse, sort by or key a map on a message. Where
code does, give it an id: an enum, the stored value, the message key. A test may assert the
English text: in Rust a message is English until `pf_l10n::set_languages` runs, and
`pf_l10n::with_language` reads another language on one thread.

## Never translated

These stay literals in code, or in the message as written:

- brand and product names (`never_translate` in `l10n/glossary.json`); a label that is only a
  brand name, such as `DualSense`, stays a literal;
- key and button names used as data, host names, game titles, preset names, versions, URLs;
- units inside technical readouts: the statistics overlay lines, the speed test figures;
- log and operator text: `tracing`, `anyhow` context, `bail!`, `expect`, `eprintln!`;
- CLI output and test names.

## How a language ships

- The OS picks the language. No client has a language setting; the web console keeps its
  switch. Fallback runs `de-AT` → `de` → `en`, one message at a time. A Chinese tag without a
  script gets one: `zh-TW`, `zh-HK` and `zh-MO` read `zh-Hant`, every other `zh` reads `zh-Hans`.
- `l10n/locales.json` lists the shipped languages. A language that is not listed is a draft:
  `check` checks it, the builds ignore it. Add the language to `locales` in
  `web/project.inlang/settings.json` too: `check` fails when that list and `locales.json` differ.
- A language ships when `common`, `client` and `console` are complete and reviewed. New English
  never fails a build for want of a translation. At a release, a language under 95% on the parts
  a surface needs is left out of that release.
- A translation is written from the meaning, the way a native app would say it, never line by
  line.
- The console kit does no complex shaping and no right-to-left. Arabic, Hebrew and the Indic
  scripts ship once it does. Chinese, Japanese and Korean: the next section.

## Chinese, Japanese and Korean

The pipeline accepts `ja`, `ko`, `zh-Hans` and `zh-Hant`; none ships yet. Their plural rule is
other-only, so a plural message has a single arm (`l10n/SPEC.md`). Ship Chinese as `zh-Hans` and
`zh-Hant`, never bare `zh`: a `zh` tag with no script is read by region, `zh-TW`, `zh-HK` and
`zh-MO` as Traditional, every other as Simplified.

- **Fonts.** Punktfunk bundles no CJK font. The console kit draws a character Geist lacks with
  the system's font, picked for the UI language so Han characters get that region's shapes. A
  platform with no system font manager hands the kit a face through
  `Console::with_fallback_fonts` (`theme::build_fonts_with`): the console's own system font
  where it has one. A browser fetches faces as it needs them: `Console::take_missing_chars`
  names what no face drew, and `Console::add_fallback_fonts` hands faces to a live console. A
  language ships on a platform once that platform draws it.
- **Length.** The budget counts a wide character as two: Han, kana, Hangul, CJK punctuation and
  full-width forms.

For translators, on top of "from the meaning":

- A cause after ` — ` or `: ` (`{why}`, `{reason}`) is its own clause and must read as one.
- A name in a placeholder (`{host}`, `{name}`, `{title}`) can end in any sound. In Korean, word
  the sentence so no particle depends on it, or write the both-forms spelling: `을(를)`,
  `이(가)`, `(으)로`.
- Chinese and Japanese need no space around a placeholder. Korean keeps its natural spaces:
  clients break a Korean line at them.
- Use the language's own punctuation (`。`, `、`, `：`, `…`) and full-width forms where native
  apps do. Digits, units (`Mbit/s`) and product names stay ASCII.

For developers:

- Never submit on Enter during composition: the web console asks `isImeEvent`.
- A numeric field accepts full-width digits (`digitsOnly`).
- Measure terminal text in columns, not characters.
- Never join a list or a separator in code when a message can hold it.

## The census

`scripts/l10n-census.py` counts, per surface, the string literals in code that read as prose:
the text that has not moved to messages yet. A count may fall, never rise.
`scripts/ci/l10n-census/<surface>.txt` holds each count and `.list` the literals.

- A rise fails CI and prints the new literals. Move them to messages. If the surface cannot read
  messages yet, run `--update` and say why in the pull request.
- After you move text, run `--update` so the baseline follows.
- It counts a capitalized word followed by another word, or three words and placeholders with
  two words among them, outside comments, tests and log or error-context calls. It misses
  single-word labels and miscounts at the edges.

## Commands

```sh
cargo run -p pf-l10n -- check                    # one line per problem, exit 1 on any
cargo run -p pf-l10n -- check --missing          # also untranslated keys, which never fail
cargo test -p pf-l10n --all-features
python3 scripts/l10n-census.py .                 # counts per surface
python3 scripts/l10n-census.py . --check         # fails on a rise
python3 scripts/l10n-census.py . --update        # rewrites the baselines
python3 scripts/l10n-census-test.py
```
