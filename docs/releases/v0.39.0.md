Wire-compatible with 0.38.0: a new client streams from an old host and the other way round, so you can update one side at a time. The Windows display driver speaks the same protocol — a 0.38.0 driver still serves this host, though the new one carries fixes worth taking.

- **Two players on one host.** Each stream can get its own Steam sign-in, its own controllers and its own player number, and a second client on a Windows host gets a display of its own instead of a refusal.
- **A launch waits for the game.** Every client holds the title's cover until the game's window is up — and says so when a launch fails or the host's Steam needs a sign-in, instead of dropping you on a desktop.
- **10-bit SDR** on AMD (Windows and Linux), Intel (Linux) and NVIDIA (Linux): smooth gradients without an HDR screen. Apple clients decode and draw it at ten bits, and webOS gains the setting.
- **The web console runs the host.** Host → Settings edits the settings that used to mean editing host.env, session rows mute one stream or place its player, a Controllers page shows the emulated pad live, and a restart action picks up what needs one.
- **Plugins are boxed in.** Each runs in its own sandbox under its own token; a plugin asking for folders is reviewed in the console and granted read-only by default.
- **Scrolling follows the OS.** Wheel, touch, pen and controller scrolling reach the host with their own units and momentum, so a trackpad glides and a wheel steps.
- **Moonlight devices pair with a name**, a waiting PIN announces itself to automations, and a Moonlight session takes the console's per-session controls like a native one.

## Before you update

- **The web console refuses connections from outside the local network** on every bind — loopback, LAN and VPN ranges (Tailscale included) still reach it; the open internet does not. Reach it from outside through a VPN or a tunnel that ends on the host.
- **Windows hosts: a second client gets its own display** rather than a refusal. Set conflict handling to *reject* to keep the old behaviour.
- **Plugin authors: `launch.kind: "plugin"` no longer launches.** The catalog plugins that used it moved to `exec` and `desktop_id`, and a package without a manifest does not start while sandboxing is on.
- **The management token leaves the environment.** `--mgmt-token` is gone and `PUNKTFUNK_MGMT_TOKEN` no longer survives in the host's environment — a value set there is persisted to the mgmt-token file instead, which `ctl`, the tray and the console already read. On Windows, host.env no longer imports a key whose name carries TOKEN or PASSWORD; on NixOS a credential in `settings` is refused.

## New

### Two players on one host

- **A seat's own Steam.** On a Linux host, a session can run Steam under a home of its own — the desktop Steam keeps running and two devices play at once. Each seat signs in once, and a seat at the sign-in screen says so instead of looking stuck. Off by default; the console's host settings carry the switch, the pad filter and how many seats stay warm (one by default).
- **Each seat's Steam sees only its own controllers**, so a second player's pads never appear as Player 1's.
- **A kept display resizes instead of rebuilding.** A pre-warmed seat's gamescope changes mode to match the connecting device, so the warm Steam survives and nobody pays the cold-boot wait again.
- **The Dashboard picks each session's player number.** The pick survives reconnects — a device comes back to the slot it had — and the stats overlay names which players a session holds.
- **Mute one stream.** The console's session row, the Android ring and the Linux quick-action ring silence one session while another on the same display keeps hearing. A custom library entry can name who hears a title, and the overlay says when the host — not you — muted the stream.
- **The host names sessions that share a network path.** Two sessions behind one NAT or tunnel share the link; the console's session card and `ctl stats` name the other session so a bitrate fight has an explanation.
- **Windows: a second client gets its own virtual display** by default, capped by the display limit. A second Moonlight client steals the single GameStream session, as it already did on Linux.

### Launches that wait — and answer

- **The launch hold waits for the game's window** on every client: through a Proton prefix build, a Steam launch screen or a slow splash, capped at two minutes. Show stream still reveals at once.
- **The host knows when the game's window is up on every backend** — gamescope, KWin, GNOME and Windows — so the hold lets go at the right moment everywhere, not only where windows are listed.
- **A launch that produced no game says so.** A refused or failed launch shows its reason on the stream on Linux, Windows, Mac and the console, and Android's hold gives up with a message instead of a spinner.
- **A game opening on the operator's monitor is moved to the streamed output** and focused, where the compositor reports windows.

### 10-bit SDR

- **AMD on Windows and Linux, Intel on Linux, NVIDIA on Linux.** The encoders carry ten bits under BT.709 instead of welding bit depth to HDR — HEVC Main10 everywhere, AV1 10-bit SDR on AMD and Intel.
- **Apple clients decode and present 10-bit SDR at ten bits**, so the gradients the mode exists for stop banding at the screen.
- **webOS gains the 10-bit SDR setting** — the TV decodes Main10 from the stream as it already does for HDR.

### Web console

- **Host → Settings edits the host.** Around forty-five settings — encoder, capture, audio routing, gamepads, Game Mode, discovery, updates — save on change, and a row pinned by host.env or a flag shows locked and names what pinned it. The voice-chat app list suggests apps playing audio on the host right now.
- **Restart the host service from the console.** Settings that only apply at plane start are named, and the restart sits behind the console password.
- **Per-session rows.** Stop one session, send it a keyframe, mute its audio, widen or narrow its access within what its pairing allows, and place its player — the all-sessions Stop that kicked everyone is gone.
- **Controllers page.** The pad the host emulates, drawn from what it receives — sticks, buttons, axes — with a bounded event log that pauses and copies into a bug report.
- **A summary when a session ends.** The card a screenshot can attach to a report, also readable as `GET /session/last`.
- **Plugin folder access.** A plugin's requested folders land in the console for review; grants are read-only by default and a plugin restarts only when its own grants change.
- **Windows on the streamed screen.** On Hyprland and sway a session can list the toplevels on the head it streams — a dialog behind the game is no longer invisible — with focus behind the input grant and close behind Launch.

### Moonlight

- **Name a device while its PIN is up** — the pairing card asks, instead of renaming afterward.
- **A parked pairing announces itself** to automations (`pairing.pending`), like the native knock.
- **A Moonlight session registers like a native one**: it stops by its own id, takes a keyframe, fires session events and reports its real numbers — bitrate, input, capture — instead of zeros.

### Library

- **Covers come from the host.** A remote cover is fetched once into a host-side art store and served from there, so every client stops paying the WAN round trip on every visit.
- **Clients cache poster bytes on disk** — the library opens with art already there, and a remembered library shows before a sleeping host answers on Linux and Android. Settings carries a Clear cached art row.
- **A custom library entry keeps its process hints** through a round trip in the console editor.

### Clients

- **Stream size by aspect family.** The size picker groups by shape — a 16:10 laptop, an ultrawide and the Steam Deck's 1280×800 are listed sizes now — and a phone-shaped screen leads the switch with "Screen" and "Safe area" entries.
- **Bitrate is Automatic or a fixed rate**, and the fixed rate can be typed: a Custom… row on Android's touch settings, and a typed field on Apple TV and the controller settings where no slider exists.
- **iPhone and iPad: pull two fingers in from a side bezel** to open the quick-action dial while touch passes through to the game.
- **Linux and Windows clients: Select+X cycles the stats overlay**, the chord Apple and Android already had.
- **Steam Controller 2 raw passthrough** on Linux, Windows and Android — the pickers list it and Android can test a captured pad from Settings. A phone's gyro can drive the on-screen pad.
- **Hooks filter automations on the device itself**, by its pairing fingerprint, not a display name two devices can share.

## Improved

- **HDR lands right in more places.** Every codec now sends its mastering metadata in the stream, so a decoder or TV that tone-maps from it gets the real volume. The desktop, Android PyroWave and Apple TV clients tone-map HDR onto an SDR screen with the BT.2390 curve instead of clipping highlights or landing a stop dark. Android hands the panel the stream's HDR10 volume, Apple TV follows decoded frames into the HDR display mode, a Windows host matches HDR state and SDR white to what the desktop shows, and gamescope tells DirectX games the session is HDR and lets Steam enable it headless.
- **Cheaper capture and encode on Linux hosts.** gamescope can hand over tiled AMD/Intel buffers that stay in device memory, a producer's NV12 reaches every AMD/Intel encoder without a conversion pass, and the NVIDIA raw lane converts held frames straight into the encoder's slots — less copying, lower host-side latency.
- **Advanced stats name why Automatic lowered the bitrate** — packet loss, decoder speed, a queue on the path — and how many loss repairs the client asked for in the last minute.
- **The host can play the stream's audio on its own speakers.** The *host and client* output mode lets whoever sits at the host hear the game — and on Linux and Windows alike, voice-chat apps like Discord stay on the host's output instead of looping back into the stream to the friends in the call.
- **A bug report is one file.** The host logs one link-health line per session per minute, clients log what the wire actually delivered, and Android logs its Wi-Fi rate changes — a freezing session no longer means paging a debug ring.
- **The console marks a setting a bound preset overrides.** A row a host's preset pins shows the dot and names the preset, the host and the value it will stream at.
- **Scrolling keeps its source.** Wheel detents, trackpad and pen glide, controller flicks and gesture phases all reach the host as themselves instead of flattening into one notch-step — and each session can invert direction on its own.
- **Sharper chroma.** 4:2:0 chroma is sited on the left column at encode and centred on the right code at decode, so colored edges stop smearing; Apple's present, cursor and demo streams are colour-tagged.

## Security

- **Each plugin runs in its own sandbox under its own token**, on Linux confined to what the plugin token can reach — a plugin can no longer read the host's admin token out of the operator's home. A package without a manifest does not start while sandboxing is on, operator folder grants bind read-only by default, and the runner's proxy pins the host certificate.
- **The console password is stored as an argon2id hash.** First sign-in swaps the clear line for the hash, and writing a clear line back is the reset. Password confirmation is scoped to the session that asked, and a POST from a plugin's origin is refused when it can't prove same-site.
- **The management token is out of the environment and the command line**, where hooks, launched games and other local accounts could read it — see *Before you update*.
- **Artwork credentials are redacted from traces**, and an oversized concealment input is rejected instead of trusted.
