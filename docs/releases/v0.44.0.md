**Update the host first.** A 0.43 app streams from a 0.44 host, but a 0.44 app can't stream from or pair with a 0.43 host. On Windows the installer updates the host and its drivers together.

- **A desktop for each person.** Profiles give everyone on the host a name, a picture and a colour, and the apps ask who is playing. A profile can share your desktop, keep its own Steam, or get a desktop of its own: up to four people play at once on Windows Server or Linux.
- **Reachable without logging in.** A Linux host answers the apps from boot, with the lock screen still on its monitor.
- **One port.** Every stream uses UDP 9777 alone. There is no second video port to open or forward.
- **Fewer freezes on a lossy link.** A frame missing a few packets has them sent again, the encoder skips a lost frame instead of stopping for a keyframe, and the host paces every frame to your device's link.
- **niri hosts.** A Linux host streams niri through biri, the niri build with virtual screens.
- **Steam Controllers stay themselves.** The 2015 Steam Controller and the Steam Controller 2 reach the host with their trackpads, gyro and Steam's own settings.
- **PyroWave quality** takes the bitrate row's place, and Automatic PyroWave adapts to the network.
- **The web console is rebuilt** around Home, Profiles, Devices, Displays, Library and Host.

## Before you update

- **Update the host before the apps.** A 0.44 app says to update both, or shows a 0.43 host as offline. Apps older than 0.43 must update to stream from a 0.44 host. An open browser tab says it is older than the host: reload it.
- **Open one port.** Forward or allow UDP 9777, plus 9778 for the browser client and 9779–9782 for seats. A rule for a pinned video port can go. On Windows the installer removes its old video-port rule, and the host opens 9778 itself while Browser streaming is on.
- **Windows hosts let go of a screen at once.** With nothing saved under **After a device disconnects**, a client's screen is removed as soon as it leaves, as on Linux; it used to stay 10 seconds. Set a keep-alive there, or `PUNKTFUNK_MONITOR_LINGER_MS`, to keep it.
- **Check on/off settings in host.env.** Every `PUNKTFUNK_*` switch now reads `0`, `false`, `off` and `no` as off, and anything else as on. A line such as `PUNKTFUNK_NO_AUDIO_MINT=0` used to switch the feature on and now switches it off. The configuration page lists each switch.
- **Hosts pace every stream by default.** `PUNKTFUNK_DELIVERY=burst` brings back the old behaviour; `PUNKTFUNK_PACE_BURST_KB` is gone.
- **Plugins run sandboxed.** On Windows a plugin without a manifest no longer starts, and a plugin that reads folders outside Program Files needs them declared or allowed under Plugins. RTSS Frame Cap needs a second `icacls` grant; the plugins guide has it. A box that can't build a sandbox stops the plugin runner, and Diagnostics says how to fix it.
- **Linux hosts with Steam per seat:** each device with its own Steam becomes a profile named after the device. That device keeps playing it; other devices are asked who is playing.
- **SteamOS canary:** switch with `git switch main`, then `update.sh --pull`. `update.sh --channel` now stops with an error.
- **Web console bookmarks:** old addresses such as `/pairing`, `/stats` and `/logs` redirect for this release only.

## New

### Profiles and seats

- **Profiles.** One per person, up to eight, with a name, a picture and a colour; the owner's exists from the start. Each plays where it says: on your desktop, with its own Steam (Linux), or on its own desktop. Add and remove them on the web console's Profiles page.
- **Who is playing.** Apple, Android, Linux and Windows apps, Decky and the CLI ask before they connect, remember the pick per host and show it on the host card. **Switch profile** changes it. The console asks on every connect unless you turn on **Remember on this device**. A link's `as=` plays as a profile once. Moonlight plays as the owner.
- **Own desktop on Windows Server 2025.** A profile gets a Windows account and a desktop of its own, up to four beside the console desktop. Under Profiles → Seats, **Set up Remote Desktop** installs the role and licensing, and Doctor names each missing step with its fix and counts down Windows' days without a licence server. Each seat gets its own copy of Steam (about 1.7 GB), lists the host's games, and gives each DualSense its own speaker and haptics. Seats stream SDR. Windows 11 runs one desktop at a time; its profiles share the owner's.
- **Own desktop on Linux.** A profile gets a system user, a session and a headless KWin or gamescope desktop, up to four including the owner. It ships as the `punktfunk-seats` package.
- **Seat Game Mode.** Return to Gaming Mode on a Linux seat opens Steam Game Mode on that seat alone. The host's own session is never touched, and Game Mode survives a disconnect.
- **Controllers on a Linux seat.** Every pad kind, up to eight per seat, visible only to that seat.
- **Shared games.** Linux seats show the owner's Steam libraries and install into one shared folder; turn off **Seats update your games** to keep them read-only.
- **Seats wake on demand.** Picking a stopped seat starts it while the app waits with Cancel. Seats of recent players start with the host, and an idle seat stops after four hours. A dropped session resumes on its seat.
- **One console for every desktop.** Home lists the sessions on every seat, and Library, Sources and Plugins switch between seats.
- **Uninstalling turns seats off** on Windows, and `punktfunk-host seats off` does it without the service.

### Reachable without logging in

- **A Linux host answers from boot.** Turn it on under Profiles. The host pairs and serves the console while the lock screen stays on its monitor. Your profile starts your session in the background, and logging in at the machine takes it over while the stream reconnects. It needs the `punktfunk-seats` package; the switch names any other missing step.

### Network

- **Resend.** A frame up to eight packets short is completed by a resend when the round trip fits in a frame, instead of a keyframe request. PyroWave frames get it too.
- **Lost frames are skipped.** While the link loses packets, the host encodes only against frames your device confirmed. Covers Vulkan Video, VA-API, NVENC, AMF, QSV and the Windows display driver's encoder; not AV1 on NVENC or QSV, and not PyroWave.
- **Pacing at the measured link.** The device learns its link from both ends' port speeds, then from what the start-up ramp proved, and tells the host. The stats overlay and the console's session row say what paces the link.
- **Automatic bitrate reads loss by where it falls.** A filling queue lowers the rate; random loss no longer does, and one lost frame stays a blip.

### PyroWave

- **PyroWave quality,** from 0.5 to 2, replaces the grey bitrate row on Linux, Windows, Apple, Android and the console. It reads as the bitrate it needs at your mode and warns when Wi-Fi or a slow port falls short.
- **Automatic PyroWave adapts** to the network. Held at its floor for three seconds, the overlay says the network is weak and names a codec that would look better.

### niri

- **niri hosts, through biri.** biri is the niri build that adds virtual screens; it needs a build from 2026-09-04 or later. Each device gets a screen of its own at its size and refresh rate, resized mid-stream, with keyboard, mouse and clipboard, and library games open on it. SDR only, and so far run on NVIDIA alone. Stock niri streams a pinned monitor and says plainly why it can't do more. X11 games need `xwayland-satellite`.

### Windows host

- **Stream a monitor.** **Streamed screen** mirrors a chosen physical monitor or another session's display. A session that starts on the lock screen or a Windows prompt opens the virtual display instead.
- **Shares the screen** joins the owner's live virtual display instead of opening a second one.
- **Desktop audio from a named output** with `PUNKTFUNK_LOOPBACK_DEVICE`, for boxes with several outputs.

### Linux host

- **Monitors come back after a crash.** A host killed mid-stream no longer leaves the desk dark: the next start restores the monitors and removes its own screen, on KWin, Hyprland, sway and gamescope.

### Controllers

- **The 2015 Steam Controller passes through as itself** to Linux and Windows hosts, with trackpads, gyro and haptics: from Linux and Windows apps by cable or dongle, from Android by USB or Bluetooth, and from a Mac, iPhone, iPad or Apple TV with the Steam Controller 2 switch on. Bluetooth needs Valve's Bluetooth firmware, which Steam installs over the cable.
- **Steam Controller 2 keeps its identity.** Steam on the host sees the same controller as over a cable, with its layouts and gyro calibration, from Linux, Windows, Mac and Android. Several pads on one Puck share one virtual Puck, and gyro no longer drops out after a lost packet.
- **Controller type** in the quick-action dial switches between Automatic, Xbox 360, Xbox One, DualSense, DualShock 4 and Steam Deck mid-stream.
- **Android captures a Steam Controller 2** whenever controller forwarding is on; the separate switch is gone. An AYN handheld's rear M1 and M2 reach the host as the back grips.

### Apps

- **Keep screen awake,** on by default. Off, a stream holds the screen only while you play, so the device's own sleep takes over a game left alone.
- **Render scale** takes any percent from 50 to 400.
- **Phones hold landscape** under the stream and the console. A foldable iPhone set down half open puts the picture on the upright half and the controls on the flat half.
- **Android:** a title's menu offers **Add to home screen** and **Save launcher file**, so a launcher such as Cocoon starts the game.
- **Windows app:** the console opens when a controller connects, and the host list sorts and groups like the console's.
- **Spanish** for the web console.

### Hosts

- **Tray autostart** is a host setting, on by default, with a **Start at log-in** item in the tray. SteamOS installs the tray too.
- **Display refresh multiple** is an Advanced Video row in the console.
- **NVENC preset** from host.env: `PUNKTFUNK_NVENC_PRESET` 1 to 7. A slower preset adds latency to every frame.
- **ROM Manager** starts a game in the host's best copy of its emulator. The Emulators card adds **Use my copy** for a portable build, firmware status and save backups.

### Web console

- **New layout.** The sidebar is Home, Profiles, Devices, Displays, Library and Host, then Diagnostics, Automation, Plugins and Settings.
- **Home** shows what needs attention, every live session and recent events, and says when another device took the screen.
- **Devices** is one list: waiting devices first, then paired ones with their access and display.
- **Displays** is one list of screens, and presets are cards that preview on the map.
- **Host** is one page with a search across every setting.
- **Library** shows three posters across on a phone and up to seven on a desktop. A title opens on wide artwork with launches and time played.

### Console

- **Controller cards draw each pad,** and Test controller opens from the card, so a TV remote reaches it.
- **Settings → Stream controls** shows each control as the button you press, and a keyboard's shortcuts as keycaps.
- **The on-screen keyboard has Shift,** and the field you type in rides above the keys.
- **OK on Bitrate opens a custom rate.**
- **The games grid fills a wide screen,** and the games bar shows icons where it had words.

## Improved

- **Pairing ends at paired.** After the PIN, the app saves the host and returns to the list; Connect streams. A link that started the pairing carries on into its connect.
- **Request access works while another device streams,** and the app saves the host as paired.
- **Hosts encode with as many slices as the client asks.** A GameStream client asking for eight gets eight, and Windows NVENC no longer encodes a single slice.
- **Linux hosts with NVIDIA** keep up under a GPU-heavy game: the frame conversion runs at raised GPU priority.
- **NVENC at 120 Hz** winds its catch-up back once the frame rate holds, instead of adding latency for the rest of the session.
- **Linux and Windows apps** say when this device can't keep up with the stream at its resolution. An unknown decoder setting falls back to Automatic, and a failing V4L2 decoder tries Vulkan Video before software.
- **Linux and Windows apps** draw PyroWave straight to the screen, one pass fewer per frame. **Android** decodes PyroWave faster on Qualcomm and Arm GPUs.
- **Apple apps** turn on Game Mode on iOS and iPadOS 18.6 and macOS 26, keep the last run's log for Send logs, and show the time a frame really took to reach the screen. HDR on iPad reaches the screen sooner.
- **Bitrate steps** every 5 Mbps from 5 to 50 on Android and Apple TV; the console adds 35, 45, 70 and 90.
- **Windows hosts** pick up Steam's audio drivers after Steam's first start, without a host restart.
- **SteamOS, Steam Deck and Bazzite** ask for a restart, not a log-out, after a group change.
- **A library plugin's unchanged sync** no longer makes every app reload its library.
- **Moonlight clients** get the same HDR fallback from Linux and Windows hosts.

## Security

- **Plugins each run in their own sandbox on Windows,** with no network unless they ask, only the folders they declare or you allow, and no host token. A plugin can change only its own library rows.
- **The web console asks for its password** before adopting an emulator copy, moving emulator saves, any seats change, and a setting that widens access: GameStream, browser streaming, origins, encryption, the clipboard, or a device's access.
- **Other accounts on a Windows host can't read plugin settings** or ROM Manager tokens, and the tray needs a token minted at each start.
- **Playnite, Hydra and Game Bar launches** read only the machine's registry and the signed-in player's, so another account can't plant a program the host starts.
- **Emulator installers run as the player,** not as SYSTEM from a folder every account can write.
- **The plugin sandbox refuses the host's configuration folder** wherever it lives.
- **Linux seats stay apart:** seat accounts can't power off the host or read its keyboards, the owner's pads are hidden from seats, and each seat keeps its own identity. The seat service keeps its files where only root can change them and refuses planted links, and the updater writes its result in a folder of its own.
- **Windows seats keep Remote Desktop off the network** unless you allow it, Remote Desktop's own firewall rules included.
- **Windows virtual pads and mouse belong to their session,** so a Remote Desktop session no longer sees the host's pads.
- **A malformed AV1 or H.265 stream** no longer crashes the decoder in the Linux and Windows apps.
- **The command line pins the right host** when it requests access from a box with two systems.
- **Windows audio capture** takes the fix for RUSTSEC-2026-0332.

## Known issues

- **Steam on a Windows seat and on the PC close each other.** Starting Steam on the PC closes a seat's Steam, so start it on the PC first. While a seat's Steam is open, a Steam link or the Steam shortcut on the PC can close the PC's Steam (#1873).
- **Steam that is open on a Windows seat takes no links or launches.** Its desktop shortcut, a Steam link and a Steam game started from the app's library do nothing. Open Steam from its tray icon and start the game there (#1873).
