Works with 0.46 apps and hosts, in either order. If you run the browser client, update its page to 0.4.0 together with your hosts, and read Before you update: pairing a browser through the page changes.

- **The browser client is safe to reach from outside your home.** A browser that comes through the page's server can no longer be approved as if it were at home, and the page relays only what a browser client needs. Opening the page to the internet is now a supported setup: with Tailscale, or a domain with a real certificate. See [Browser client](https://docs.punktfunk.unom.io/docs/browser-client).
- **A profile can run on a family member's own Linux account.** They open it from their phone, tablet, PC or TV box with their account password, and can stay signed in with Face ID, a fingerprint or Windows Hello. The box keeps no copy of the password.
- **Apple apps keep their memory flat in long sessions.** They held on to decoded pictures they had stopped drawing, up to 2.4 GB at 4K.
- **Bazzite hosts survive a major update.** Moving from Bazzite 44 to 45 removed the host, the console and the update command without a word. Now the host comes back by itself on the next boot.
- **Seats see the owner's game libraries from their desktop** and install large games onto the library's own drive.
- **A Steam Controller reaches the host as soon as it is declared,** at rest or moved only by trackpad or gyro. A host with its own Steam Controller Puck keeps a Steam Controller 2 as itself.
- **A TV-only Windows box keeps its sound on the TV** after a stream ends and after a reboot.

## Before you update

- **Pairing a browser that comes through the browser client's page.** A browser that reaches the host through the machine that runs the page can no longer be approved with one click. That covers browsers outside your network and browsers on a network that blocks UDP. The PIN from **Pair a device** no longer works for such a browser either. Under **Devices**, click **Arm PIN** on its row and type that PIN into the page. Browsers that are already paired keep working. A browser on the host's own network that connects directly pairs as before.
- **The first browser from a page at a public address.** If you open the browser client at a domain rather than an IP address or a `.local` name, and that address isn't in **Browser origins**, its first browser pairs the same way: **Arm PIN** on its row. To keep **Approve**, add the address to **Browser origins**. Once one browser has paired from that page, the next ones are approved as usual.
- **Windows seats on an existing account no longer run hooks.** A `hooks.json` already on such a seat is skipped. Such a seat now installs only Verified plugins too.
- **Update the browser client's page to 0.4.0 too.** The page's server now tells the host who a visitor is, and this host is the first to act on it. What changes on the page:
  - **A port forward to the default setup stops working from outside your network.** With the certificate the page makes itself, a browser on the internet can't tell your page from an impostor's. Such a browser now sees a notice instead of the client. Use Tailscale (`compose.tailscale.yaml`), or give the page a domain with a real certificate: `DOMAIN=play.example.com docker compose -f compose.public.yaml up -d`.
  - **Behind your own reverse proxy, list your domain** in `TLS_NAMES`; the page answers only to names it knows. The proxy must pass the `Host` header through with its port and send `X-Forwarded-For`. In nginx: `proxy_set_header Host $http_host;` and `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`.
  - **Opening the page by a name rather than an address.** Names ending in `.local`, `.home.arpa` or `.internal` work as before. Any other name, such as `nas.lan` or `nas.fritz.box`, must be in `TLS_NAMES`; the page names the one to add.
  - **Waking a host from the page needs a paired browser** that has connected to that host through the page in the last 30 days. After the update, connect once while the host is awake. A browser that isn't paired can no longer wake a host, and is slowed down when it sends too many requests.
  - **Reload any tab that was open across the update**, once.

## New

### Hosts

- **Linux: a profile on someone's own account.** On a Linux box, **Add profile** → **Own desktop** offers **Existing account**: type the account and its password. Linux checks the password once and keeps none. The stream is that person's own desktop.
  - **Who gets in.** A device opens the profile only with the account password, or with a key it enrolled while signed in. The profile's card lists those devices and signs any of them out, a lost phone for one, without the person's password.
  - **Wrong passwords.** Repeated wrong passwords are slowed down, then locked out for 15 minutes.
  - **What the box runs there.** Nothing chosen by the box: no hooks and no plugins, and the console manages no emulators there. A game the person starts from their own device runs as usual. When it exits, the stream returns to their desktop.
  - **KDE.** Keyboard and mouse come straight from KWin 6.1 or later, since such an account has no screen-sharing grant.

### Apps

- **A locked profile asks for its password.** The Apple, Android, Windows and Linux apps, and their console modes, show a padlock on such a profile and ask before they connect. A switch keeps the device signed in: Face ID, Touch ID or Optic ID on Apple devices, a fingerprint on Android, Windows Hello on Windows, stay signed in on Linux. A password goes only to a host this device has paired with. The browser client and the webOS and Samsung TV apps can't open such a profile yet.
- **The controller keyboard has a symbols layer,** so a pad can type most passwords. A Steam Deck and an Apple TV type a password on it instead of the system keyboard.

## Security

- **A browser client's page that is reachable from the internet can no longer be used to pair as if from home.** Whatever comes through the page's machine is treated as coming from the internet, whatever address it names.
- **Someone trying PINs from outside can no longer block pairing at home.**
- **A pairing request shows the page it came from.** A request from a public website nobody has paired from can't be approved with one click.
- **The browser streaming port** checks a sender's address before doing work for it, and limits how many connections wait to be admitted.
- **The browser client's page** no longer reaches anything on your network except Punktfunk hosts, and only for the requests a browser client makes. Other websites can no longer use it. A browser's sign-in goes only to the host it paired with.

## Fixed

### Hosts

- **GTX 10-series hosts with gamescope.** The picture showed horizontal bands or blocks out of order. gamescope `+pfhdr32` now lays the capture out as the host reads it, and the host reads the buffer through the memory the card laid it out in. If your card still shows bands, tell us. `PUNKTFUNK_NVENC_RM_IMPORT=0` keeps the old mapping.
- **Bazzite.** After a major update refused the host's image, a boot unit fetches the matching one and starts your services again. Your firewall zone comes back too, and a fetch that stalls gives up instead of hanging.
- **Seats.**
  - Steam opened from a seat's desktop sees the owner's libraries.
  - A seat installs and downloads on the library's own drive, not its small system disk.
  - A seat that fails to stop no longer leaves the owner's libraries mounted until a reboot.
- **Steam Controller.**
  - A Steam Controller at rest, or moved only by trackpad or gyro, no longer stays invisible to the host.
  - A host with its own Steam Controller Puck no longer turns a streamed Steam Controller 2 into a DualSense.
- **Windows: a TV-only box.** Punktfunk's own speakers hide while nothing streams, so Windows keeps the TV as the sound device. A restore that found the TV missing tries again when it comes back.
- **gamescope launches.** An AppImage started from Steam in a host's own gamescope mounts again, and `sudo` and `pkexec` work there.
- **Plugins with no page,** such as RTSS Frame Cap, show as running.
- **Logs.** An Apple app that sends two logs at once keeps both. The log of a run that crashed was overwritten.

### Apps

- **Apple apps.** The memory leak above is fixed. When an Apple TV's picture freezes, the log now names the frame the GPU stalled on.
- **Linux app.**
  - GTX 10-series cards decode on the GPU instead of in software.
  - A device whose driver refuses a codec no longer asks the host for it, which re-dialled on every launch.
  - A second launch from a shortcut or link no longer leaves a stuck process.
- **Android.**
  - On a Chromebook, a two-finger touchpad swipe scrolls instead of moving the pointer.
  - A Shield on a TV that runs a hair slower than the stream drops and repeats far fewer frames.
- **Web console.** A ticked checkbox shows as ticked, and text keeps each font's own spacing.
- **winget** names the privacy policy on the host's package page.
